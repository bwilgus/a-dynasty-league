# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal fantasy football dynasty league project: a set of standalone Python scripts that scrape/ingest league history into a single SQLite database (`dynasty_data.db`), plus a Streamlit dashboard (`app.py`) that reads from it. There is no test suite, build step, or package structure — every `.py` file in the root is a self-contained script run directly with `python`.

## Commands

```bash
pip install -r requirements.txt   # streamlit, pandas, espn-api, matplotlib
streamlit run app.py              # launch the dashboard
python sleeper_to_db.py           # re-ingest current Sleeper season (see below)
python backfill_manager_efficiency.py   # recompute manager_efficiency from games/lineups
python build_standings.py         # recompute standings from games/manager_efficiency
python build_playoff_results.py   # recompute playoff_results/champions from games
python normalize_transactions.py  # normalize transactions.trans_type to Sleeper's canonical values
python backfill_pick_transactions.py   # backfill pick_transactions for all Sleeper seasons (2024+)
python normalize_player_ids.py    # normalize lineups/draft_picks player_id to Sleeper's ID space
```

Scraper/one-off scripts (`owner_scraper.py`, `update_sleeper_draft.py`, `espn_scraper_2017_2018.py`, `espn_transaction_recreation_2017.py`, `espn_player_name_fixer.py`, `transaction_test.py`) are run ad hoc and generally need a league/draft ID edited in the file or entered at an interactive prompt — check each file's top-of-file constants before running.

**Always back up `dynasty_data.db` (`cp dynasty_data.db dynasty_data.db.bak`) before running any script that writes to it.** Several scripts do full-table `DROP`/`INSERT OR REPLACE` operations.

## Architecture

### Everything revolves around `dynasty_data.db`

There's no ORM or schema file — table shapes are only discoverable via `PRAGMA table_info(...)` / `sqlite_master`, or by reading the `INSERT`/`CREATE TABLE` statements in the scripts that populate them. Key tables: `teams`, `standings`, `games`, `lineups`, `manager_efficiency`, `playoff_results`, `champions`, `draft_picks`, `transactions`, `pick_transactions`, `owners`, `divisions`, `power_rankings`.

`archive_df_final` is a legacy, pre-normalization table (originally named `df_final`) from whatever tool/spreadsheet seeded this database's schema. It covers only 2014–2020, keys managers by bare first name instead of `team_id` (some of whom, e.g. "Alan", "John", "Michael", "Bryan", aren't even in the current `owners` table — they left before the Sleeper era), and isn't joined against anything else. Treat it as read-only historical reference, not a table to build features on — `champions`/`playoff_results` are its normalized, `team_id`-keyed replacement (validated to agree with it exactly for all 7 overlapping years).

### Two kinds of scripts

1. **Ingestion scripts** — pull from an external API/source and write raw per-season data (`teams`, `standings` historically, `games`, `lineups`, `transactions`, `draft_picks`). One script per data era (see below).
2. **Derived-table scripts** (`backfill_manager_efficiency.py`, `build_standings.py`, `build_playoff_results.py`, `normalize_transactions.py`, `normalize_player_ids.py`) — compute/clean up purely from what's already in the DB, with no external API calls (`normalize_player_ids.py` is the one exception: it fetches Sleeper's `/players/nfl` list as a reference lookup, not per-season data). They fully rebuild their target table (`DROP`/`CREATE`, `INSERT OR REPLACE`, or idempotent `UPDATE`s) and are safe to rerun any time the upstream tables change. **New derived-table work should follow this pattern** rather than re-deriving stats from a live API.
3. **Narrow backfill scripts** (`backfill_pick_transactions.py`) — hit only the specific API endpoint needed rather than a full `populate_league_data` resync, to keep blast radius small when fixing/adding one thing. Prefer this over a full resync unless you actually need to refresh everything.

### `pick_transactions`

Captures the draft-pick side of Sleeper trades (`trans_id, trade_year, trade_week, pick_season, pick_round, original_team_id, from_team_id, to_team_id`), which the `player`/`action` shape of `transactions` can't represent. `original_team_id` is whichever team's draft slot the pick is (stable across multiple re-trades of the same pick); `from_team_id`/`to_team_id` are who held it immediately before/after this specific trade. Sleeper-era only (2024+) — `sleeper_to_db.py`'s transaction loop now populates this automatically for any future season; `backfill_pick_transactions.py` filled in the seasons already in the DB by re-querying just the transactions endpoint. Pre-Sleeper (2014-2023) pick trades are not in this table — see the WordPress note below.

### Data eras & sources

The league has moved platforms twice, and `games`/`lineups` data shape differs by era:

- **2014–2016: NFL.com.** No ingestion script for this era exists in the repo — this data lives only in `dynasty_data.db` with no reproducible source. `lineups` has no rows at all for these years (no bench/slot data), so per-player stats (`manager_efficiency`, `standings.max_pf`) are not computable.
- **2017–2023: ESPN** (`espn_scraper_2017_2018.py`, `espn_transaction_recreation_2017.py`, `espn_player_name_fixer.py`). Despite its name, `espn_scraper_2017_2018.py` is generic — it prompts for a year at runtime (`populate_espn_season(year)`) and its `get_base_url` branches on `year >= 2018` (modern segment endpoint) vs `year < 2018` (`leagueHistory` endpoint) — so it's the ingestion path for the whole 2017–2023 range, not just its namesake two years. Uses ESPN's `lineupSlotId`/position IDs, stored as slot values like `D/ST`, `BE` (bench), `RB/WR/TE` (flex), `IR`.
- **2024–present: Sleeper** (`sleeper_to_db.py`, `owner_scraper.py`, `update_sleeper_draft.py`, `config.py`, `helper_defs.py`). Uses Sleeper's roster/matchup API, with slot values like `DEF`, `BN` (bench), `FLEX`. Sleeper reassigns a new `league_id` each season (chained via `previous_league_id`); `helper_defs.get_sleeper_league_id()` walks that chain, and the current one lives in `config.py`.

Any code touching `lineups`/`player_slot_position` across years must account for these different vocabularies (see `FLEX_ELIGIBILITY` in `sleeper_to_db.py` and how `backfill_manager_efficiency.py` extends it with the ESPN-era alias).

### Known data caveats

- **2017 `lineups.player_slot_position` is corrupted**: every row reads `"QB"` regardless of the player's actual slot, from how `espn_scraper_2017_2018.py` handles the `leagueHistory` endpoint (the `year < 2018` branch of `get_base_url`). Not fixed — 2017 is excluded from `manager_efficiency`/`standings.max_pf` as a result.
- **2017 `games` win/loss/points don't fully reconcile** with older hand-entered records (off by half a game and a few points for at least one team) — likely tied to ongoing `game_id` cleanup for that season.
- **`manager_efficiency` and `standings.max_pf` are only meaningful for year >= 2018** — no usable bench/lineup data exists before then (see above).
- **`standings` is keyed `(year, week, team_id)`** and holds regular-season-only cumulative rows (no rows for playoff weeks — wins/losses/points freeze at the end of the regular season, matching this league's existing convention). `app.py`'s `load_standings()` and the Standings tab still assume one row per team per year (`idxmax()` over the whole season) and have **not** been updated for the new shape — this is a known follow-up, not yet done.
- **This league does not use FAAB** — waivers are priority-order, not budget-bid — so there's no bid-amount data to capture from either platform's transaction API, and none should be expected.
- **The playoff bracket is championship-path only, by design.** This league never tracked consolation/"toilet bowl" games, so `games`/`playoff_results` only ever contain the winners-bracket path (verified across all 12 years: a 4-team Quarterfinal round with no byes, a 4-team Semifinal round — the 2 quarterfinal winners plus 2 teams that got a first-round bye — then a 2-team Championship). Don't read the absence of consolation games as missing data to backfill.
- **`team_id` can be `0`** (2014 has a real team, Bryan Greenberg, at `team_id=0`). Don't use falsy/truthy checks (`if team_id:`) on it in any downstream code (SQL, Python, or JS) — always compare explicitly (`team_id is not None` / `!== null`).
- **Draft-pick trade history is Sleeper-era only (2024+).** `pick_transactions` (see above) captures it going forward for any new season. Pre-Sleeper (2014–2023) pick trades are not in `pick_transactions` at all -- Sleeper's transaction API simply doesn't have that history. `draft_picks.original_roster`/`previous_owner` capture the *end result* of pick trades (who ultimately owns/used a pick) for 2017+, but not 2014–2016, and not the transaction itself (when it happened / what else was involved). https://adynastyleague.wordpress.com/the-draft/ has a per-year draft results page, and 2018+ pages include a "Via" column showing trade chains (e.g. "1.01 Steven ... via Cody") that could reconstruct pre-Sleeper pick lineage for those years. **2014-2016 specifically cannot be recovered this way and should not be re-attempted**: the 2014 page is the startup draft with no trades (nothing to backfill), and the 2015/2016 pages have no "via"/trade annotation at all -- despite draft-order anomalies implying picks did change hands, there's no source data to say who traded what to whom, and guessing from order alone risks writing wrong data. This was a deliberate decision (2025-09 session) to leave 2015/2016 pick lineage blank rather than guess.
- **`sleeper_to_db.py` no longer writes to `standings`.** It originally wrote season-final Sleeper roster stats there directly; once `standings` was rebuilt as a weekly-cumulative, `(year, week, team_id)`-keyed derived table, that old write would violate the new `NOT NULL` `week` column on every run. It was removed -- `standings` is populated solely by `build_standings.py` now. If you ever see a `NOT NULL constraint failed: standings.week` error, something reintroduced a direct write from an ingestion script.
- **`player_id` in `lineups`/`draft_picks` is normalized to Sleeper's ID space** (2025-09 session, `normalize_player_ids.py`). Before this, ESPN-era (2017–2023) and NFL.com-era (2014–2016) rows used those platforms' own IDs — e.g. Tom Brady was `2330` every ESPN year, a different value from his Sleeper ID `167`. Both tables now have `espn_player_id` (the original pre-normalization id, always preserved) and `player_id_source` (`'sleeper'` if `player_id` now holds a confirmed Sleeper-space id, `'unmatched'` if no confident match was found and `player_id` still holds the original value). D/ST rows are handled separately from name matching: both eras spell defenses as a team name, and Sleeper's own D/ST "id" is just the team abbreviation (e.g. `GB`), so it's a deterministic nickname→abbreviation lookup (`NICKNAME_TO_ABBR` in the script) rather than fuzzy matching. **Only trust `player_id` for cross-era joins where `player_id_source = 'sleeper'`** — for `'unmatched'` rows it's still whatever platform-native id it always was.
  - **Matching tiers, strongest to weakest** (never guesses when ambiguous): (0) Sleeper's own player records embed ESPN's id on ~55% of players (the `espn_id` field) — where our stored `espn_player_id` matches that field exactly, it's an authoritative, unambiguous match, applied by original id rather than by name so it fixes every spelling variant of the same person in one shot (e.g. "Robby Anderson" and "Robbie Anderson" both resolved to Sleeper's "Robbie Chosen" — his legal name change — via one shared `espn_id`). This tier alone resolved every real-name-collision case found in `lineups` (two different NFL players named "Frank Gore", "Mike Williams", and "Zach Miller" across history, plus a Sleeper-side duplicate "Ronald Jones"/"Ronald Jones II" entry for one real person — confirm via `espn_id`/birth_date/college before ever trusting a name-only guess on these). (1) exact name+position. (2) name-only, only if exactly one Sleeper player has that name. (3) a small hand-verified alias table for confirmed nickname/spelling mismatches (`VERIFIED_ALIASES` in the script, e.g. "Pat Mahomes" -> Sleeper's "Patrick Mahomes").
  - Coverage as of last run: **100% of `lineups`**, **~99% of `draft_picks`** (710/717). Remaining `draft_picks` `'unmatched'` rows (7, all 2014-startup-draft veteran picks) simply aren't in Sleeper's *current* `/players/nfl` snapshot at all (Alex Henery, Colt Lyerla, Jake Locker, Marcus Lattimore, Nate Burleson, Roy Finch, Donnell Pumphrey -- all short-career/pre-Sleeper-relevance players; it's a live endpoint, not a stable historical archive, so this happens even to real, once-relevant players). Their `player_id` was already `NULL` before this work touched anything -- there was never an id to look up in the first place.
  - Note on `draft_picks.player_name`: several entries turned out to be verbatim-correct but unusual (`'Equanimeous Tristan Imhotep J. St. Brown'` is Equanimeous St. Brown's actual full legal name, not corrupted data as first assumed; "Davante Parker" is a common misspelling of Sleeper's "DeVante Parker") or plain surname typos in the original source data confirmed via `draft_picks.nfl_team` matching the real drafting team (`'Diontae Jackson'` on PIT is actually Diontae Johnson; also fixed: Rashad->Rashard Higgins, Javorious->Javorius Allen, Josh Scobey->Scobee, Jay Feeley->Feely, Steven->Stephen Hauschka) -- these are captured as `VERIFIED_ALIASES` entries in the script, same mechanism as the nickname aliases.
  - Two ambiguous name-collision cases were resolved by hand using external identity confirmation rather than any signal in the data itself, and applied as one-off `UPDATE ... WHERE year=... AND round=... AND pick_no=...` statements (not scriptable, since the ambiguity is real -- two different actual NFL players share the name and neither `espn_id` nor `nfl_team` distinguishes them in that row): the 2014 "Mike Williams" pick (round 24) is the Syracuse-era Williams (id `748`), vs. the 2017 rookie pick (round 1, `nfl_team='LAC'`) which is the Clemson/Chargers Williams (id `4068`); the 2014 "Zach Miller" pick (round 21) is the Nebraska-Omaha-era Miller who played for Jacksonville and Chicago (id `749`), a free agent at the time of that draft.
  - This also fixed a real pre-existing bug: `sleeper_to_db.py` stored D/ST `player_id` as `NULL` for 2024+ rows (its `int(pid)` coercion silently failed on non-numeric team codes like `"SEA"` and fell back to `None`). Fixed at the source in `sleeper_to_db.py` and backfilled for existing rows.
